# GCC PDP-6 920501 `vsprintf` duplicate: real formatter ownership (v1)

Date: 2026-11-20. Scope: only `pdp10-testkit`. This report **corrects
the diagnosis**, not the recorded `link_fail` result, from
`PDP10-P1-920501-MANYARGS-CLOSURE-20261120-v1.md`. No historical
original source, installed linker, C compiler, library, other
repository or guest ABI has been modified. No full sweep ran.

## The observed original failure

The exact original `tests/todo/generic/920501-8.c` is unchanged at
SHA256 `21884df76c9d24d4d4808d78de8e8a4e7909fffd1ee26a72f96f4be00a22b56a`.
Its generated GCC PDP-6 O0 assembly references both `printf` and
`sprintf`. The testkit's `freestanding_selection_v1.py` chooses the
real installed `p10stdio-format-v2.s` for GCC `sprintf`;
this fragment defines both `sprintf` and `vsprintf`.

The normal `p10run` linker environment also supplies installed
`$PDP10_PREFIX/lib/libc.a` for unresolved hosted functions such as
`printf`, plus canonical GCC `libgcc.a` for `__main`. **The runtime
archive supplies its own `printf`, `sprintf`, `vsprintf`, `vprintf`**.
When the original references `printf`, that hosted archive's formatter
group becomes needed while the standalone freestanding formatter has
already defined `vsprintf`. The conflict is *two provider objects*
for a shared symbol, not two definitions in the compiler-generated
source and not, by itself, a proved `dlink` duplicate-symbol bug.

## Controlled live dlink replay

The exact six source-identified `.dobj` inputs generated by the
original failed native GCC O0 run were archived and replayed in their
original order. The two canonical libraries are the currently
installed unmodified production archives. Three controlled links:

| Inputs | Genuine `dlink` observation |
| --- | --- |
| Six original `.dobj`, including `p10stdio-format-v2`, plus default `libc.a` and canonical `libgcc.a` | **FAIL** `dlink: duplicate global: vsprintf` |
| Identical inputs, except no separate `p10stdio-format-v2`, with the same two archives | **LINK PASS**: map contains exactly one each of `printf`, `sprintf`, `vsprintf`, `vprintf` and `__main` |
| All six original `.dobj` and canonical `libgcc.a`, but no default `libc.a` | **FAIL** `dlink: undefined symbol: printf` |

The replayed six explicit objects have **one `DEF vsprintf`** in
their symbol tables, in the standalone formatter object only. The
successful second link demonstrates that the default archive
already owns a complete hosted formatter group. It is a **link**
success only: it does not prove that the archive's hosted 16-argument
formatting/varargs ABI or console output runs correctly on PDP-6.

The evidence archive
`refs/p10tk-p1-920501-stdio-provider-20261120-v1.tar.gz`
contains the exact six `.dobj` inputs, three genuine `dlink`
console outcomes, and the complete successful map. The manifest
`PDP10-P1-920501-STDIO-PROVIDER-EVIDENCE-20261120-v1.tsv`
pins all ten members by SHA256. For reproducibility, the

## Required correction and remaining work

The previous `vsprintf` failure classification **remains `link_fail`**,
but the current evidence attributes it to a conflicting pair of
stdio providers in the testkit/runner linking policy, **not to an
established linker or assembler implementation bug**. The unrelated
`dlink: duplicate global: exit` in `980707-1.c` has not been
re-diagnosed here and remains open.

Do not simply suppress a linker diagnostic or drop one provider
without independently validating the resulting GCC variadic call
convention and real hosted console support. The separate `920501`
compiler companion retains all six genuine `sprintf` `%f`
`run_fail` guest outcomes. A correct future fix needs coherent
hosted/freestanding formatter ownership and target ABI validation.
