# P1 980605 exact-size stack and argument oracle v1

Date: 2026-11-20. Scope: `pdp10-testkit` only. This work does not run
the full compiler/CPU/optimization matrix, alter KCC/GCC, install a libc,
or modify the unchanged original `tests/todo/generic/980605-1.c`.

## Original test and the untested operation

The historical source `980605-1.c` (SHA256
`c39f1bc923a64bec734b111ff3b9025da1095a3471a7e568b2b32ff9fb951642`)
checks the arithmetic total 227 after ten local `getval()` results,
another ten results in `f2(17.0)`, and conversion of the double to
`unsigned short`. Its local `char ar[STACK_SIZE/2]` uses the default
`STACK_SIZE=200000`, but **never reads or writes `ar`**. The source
formats the integer total through `sprintf` without inspecting `buf`.
An original PASS therefore establishes neither the large live frame nor
the formatted output.

## Separate native C89 companion

`tests/semantic/regression/pdp10-stack-tenargs-fp-frame-v1.c` is
registered in the normal semantic compiler matrix. It tests an actual
`volatile unsigned char frame_v1[100000]` on the stack. The exact
100000 9-bit-byte extent occupies 25000 36-bit words. It writes 391
different 256-byte-spaced slots and the final byte, checks the
independent sum of positions 5 through 395 (78200), and checks both
the first and highest byte offsets **after** the nested ten-argument
call. It explicitly checks the `17.0` to `unsigned short` conversion,
all twenty sequential `getval` effects, the sum 227, the target's real
`sprintf` return count and all five output bytes `227\n\0`.

This companion is not a reduced-size fake stack substitute. It uses
no custom allocator, missing-libc stub or OS service. Its active
PDP-6 KCC/GCC cells pass with the actual installed toolchain, including
the GCC optimized profiles. Other native CPU entries are **pending**;
they have not been executed in this P1 closure.
